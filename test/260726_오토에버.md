# 1번. 서버 스케줄링

## 문제 복원

`dataSize[t]`, `dataTime[t]`가 주어진다. 인덱스 `t`는 데이터가 들어오는 시각(초)이고,
`t = 0 … N-1` 순서대로 데이터가 도착한다.

- 서버는 처음에 **0개**
- 데이터 도착 시각에 **가용 서버가 없으면 즉시 새 서버를 생성**
- 서버는 한 번에 하나의 데이터만 처리
- `t`초에 처리시간 `d`인 데이터를 받으면 `t ~ t+d-1` 점유, **`t+d`부터 다시 가용**

**서버 선택 우선순위**

1. 가용 서버 중 **지금까지 처리한 누적 데이터 크기가 가장 작은** 서버
2. 동점이면 아무거나
3. 가용 서버가 없으면 새로 생성

**출력**: 모든 데이터 처리 후, 서버별 누적 처리 크기의 **최댓값**

**제약**

| 항목 | 범위 |
|---|---|
| N (데이터 수) | ≤ 200,000 |
| dataSize[t] | ≤ 1,000,000,000 |
| dataTime[t] | ≤ 1,000,000,000 |

> 누적 합이 최대 `2 × 10^14`까지 간다. Java/C++이면 `long` 필수. 파이썬은 신경 안 써도 됨.

## 예제

`dataSize = [2, 2, 3, 4, 5]`, `dataTime = [4, 1, 2, 4, 5]`

| t | 데이터 | 가용 서버 | 선택 | 결과 |
|---|---|---|---|---|
| 0 | (2, 4) | 없음 | S1 신규 | S1 = 2, `free@4` |
| 1 | (2, 1) | 없음 | S2 신규 | S2 = 2, `free@2` |
| 2 | (3, 2) | S2(2) | S2 | S2 = 5, `free@4` |
| 3 | (4, 4) | 없음 | S3 신규 | S3 = 4, `free@7` |
| 4 | (5, 5) | S1(2), S2(5) | S1 | S1 = 7, `free@9` |

최종 누적 → S1 = 7, S2 = 5, S3 = 4 → **답 7**

### "동점이면 아무거나"가 답을 안 바꾸는 이유

두 서버가 **동시에 가용 상태**이고 누적값도 같으면, 앞으로의 상태 `(누적, 가용여부)`가 완전히 동일하다.
서로 교환해도 결과가 같으므로 어느 쪽을 골라도 무관. (풀리는 시각이 달랐어도 이미 둘 다 풀린 상태면 의미 없음)

## 1단계 — 시험장에서 제일 먼저 짤 코드 (브루트포스)

문제를 글자 그대로 옮기기만 한다. **이 코드는 100% 정답이다. 느릴 뿐.**

```python
def solve_slow(dataSize, dataTime):
    servers = []   # [풀리는시각, 누적처리량]
    answer = 0

    for t in range(len(dataSize)):
        # 가용 서버 중 누적처리량이 가장 작은 놈 찾기
        pick = -1
        for i in range(len(servers)):
            if servers[i][0] <= t:                      # 지금 놀고 있음
                if pick == -1 or servers[i][1] < servers[pick][1]:
                    pick = i

        if pick == -1:                                  # 놀고 있는 놈이 없음
            servers.append([0, 0])                      # 새 서버 생성
            pick = len(servers) - 1

        servers[pick][1] += dataSize[t]                 # 일 시키기
        servers[pick][0] = t + dataTime[t]              # 언제까지 바쁜지 기록

        if servers[pick][1] > answer:
            answer = servers[pick][1]

    return answer
```

## 2단계 — 뭐가 느린지 한 줄로 지목

느린 건 안쪽 `for i in range(len(servers))` 하나뿐. 여기서 하는 일은 정확히 두 가지다.

- **(A)** 놀고 있는 놈 골라내기 → `servers[i][0] <= t`
- **(B)** 그중 누적처리량 최소 찾기 → `servers[i][1]` 비교

> **"최소 하나 찾기"는 힙이다.** ← 반사적으로 나와야 하는 매칭

문제는 **최솟값 기준이 두 개**라는 것. **힙은 정렬 기준을 하나밖에 못 갖는다.**
크기 기준으로 힙을 만들면 가용 여부는 힙이 안 도와주고, 결국 손으로 다 까봐야 한다. ← 실제 시험에서 터진 지점

## 3단계 — 기준이 두 개면 힙을 두 개 만든다

**이 문제의 유일한 아이디어.** 나머지는 그냥 구현.

> 알바생을 **쉬는 방**과 **일하는 방**, 두 방에 나눠서 관리한다.
> - 쉬는 방 줄 서는 기준 → **일 적게 한 순서**
> - 일하는 방 줄 서는 기준 → **빨리 끝나는 순서**

각 방에 기준이 딱 하나씩이라 충돌이 없다. 매 초 하는 일은 3줄로 정리된다.

1. 일하는 방에서 **끝난 사람 꺼내서** 쉬는 방으로 보낸다
2. 쉬는 방 **맨 앞사람**을 부른다 (없으면 새로 뽑는다)
3. 일 시키고 **일하는 방으로** 보낸다

## 정답 코드

```python
import heapq

def solve(dataSize, dataTime):
    resting_servers = []   # 쉬는 서버: 누적처리량 (적은 순)
    working_servers = []   # 일하는 서버: (풀리는시각, 누적처리량) (빨리 풀리는 순)
    answer = 0

    for t in range(len(dataSize)):
        now_size = dataSize[t]
        now_time = dataTime[t]

        # 1) t초에 일이 끝난 서버들을 쉬는 쪽으로 옮긴다
        while len(working_servers) > 0:
            front = working_servers[0]       # 가장 빨리 풀리는 서버
            free_time = front[0]
            if free_time > t:
                break                        # 얘도 아직이면 뒤는 볼 필요 없음

            finished = heapq.heappop(working_servers)
            finished_load = finished[1]
            heapq.heappush(resting_servers, finished_load)

        # 2) 일 시킬 서버 정하기
        if len(resting_servers) > 0:
            my_load = heapq.heappop(resting_servers)    # 제일 적게 일한 서버
        else:
            my_load = 0                                 # 새 서버 (누적 0)

        # 3) 일 시키고 다시 일하는 쪽으로
        my_load = my_load + now_size
        if my_load > answer:
            answer = my_load

        heapq.heappush(working_servers, (t + now_time, my_load))

    return answer
```

브루트포스와 한 줄씩 대응된다. 새로운 개념은 하나도 안 들어갔다 (`heappop`, `heappush`, `while`뿐).

> **데이터가 없는 초가 존재하는 버전이었다면** → 루프 맨 앞에 `if dataSize[t] == 0: continue` 한 줄 추가

## 실제로 제출했던 코드가 왜 터졌나

```python
# 실제 제출 (기억 복원) — 크기 기준 힙 하나만 사용
def findServer(nowTime):
    tmpList = []
    while serverQueue:
        next = heappop(serverQueue)
        if next[1] > nowTime:          # 점유 중 → 임시 보관
            tmpList.append(next)
            localCnt += 1
            # localCnt == serverCnt면 탈출 → 가용 서버 없음 → -1 리턴
        else:                          # 가용
            serverQueue += tmpList
            heapify(serverQueue)       # 아까 뽑은 거 도로 넣기
            return next[2]
    return -1
```

### 문제점

힙을 **크기 기준으로만** 정렬해놨기 때문에, "크기 최소 + 가용" 서버를 찾으려면
top부터 까면서 **점유 중인 놈을 전부 꺼내 `tmpList`에 쌓아야** 한다.
즉 가용 서버 앞에 깔린 점유 서버 개수만큼 매번 pop/push가 발생.

`localCnt == serverCnt` 탈출 조건은 **조기 탈출이 아니다.** 전부 점유 상태일 때
localCnt가 serverCnt에 도달하는 시점은 이미 다 꺼낸 뒤다. 그냥 전수 스캔의 종료 조건.

`serverQueue += tmpList` + `heapify()`도 호출당 O(K)라 상수가 한 번 더 붙는다.

### 최악 케이스

```python
N = 200000
dataSize = [1] * N
dataTime = [10**9] * N   # 아무 서버도 절대 안 풀림
```

- t=0: 서버 0개 → 즉시 -1
- t=1: 서버 1개 전부 점유 → 1번 pop 후 -1
- t=2: 서버 2개 전부 점유 → 2번 pop 후 -1
- …
- t=199999: 199,999번 pop 후 -1

합계 `1+2+…+200000 ≈ 2 × 10^10`회 힙 연산. **C++로 짜도 못 뚫는다.**

### 테케는 왜 뚫렸나

`dataTime`이 작으면 서버가 몇 개 안 생긴다. 전부 1이면 서버는 1개, 스캔 길이도 1이라 O(N).
**서버 개수 K에 대해 O(N·K log K)** 구조라 K가 작은 입력에서만 살아남는다.
채점 데이터에 dataTime 큰 케이스가 섞여 있으면 그대로 사망.

### 새 코드는 왜 안 터지나

- **일하는 방에서 진짜 끝난 사람만 꺼낸다.** 힙 맨 앞이 아직 안 끝났으면 뒤는 전부 안 끝난 것 → `break`
- 한 서버가 `일하는 방 → 쉬는 방`으로 넘어가는 건 **작업 하나당 정확히 1회.**
  작업이 N개니까 이동도 총 O(N). 힙 연산 총합 `4N ≈ 80만`회
- 원래 코드는 **같은 서버를 매 초 반복해서** 꺼냈다 넣었다 한 것. 그게 O(N) vs O(N·K)의 차이

### 서버 번호(`serverNum`, `globalSize[]`, `serverCnt`)는 왜 사라졌나

최종 답이 "누적 크기의 최댓값"이라 **누가 몇 번 서버인지는 아무 상관이 없다.**
필요한 정보는 `누적처리량`과 `풀리는시각` 둘뿐.

> **습관화할 것: 답에 안 쓰이는 정보는 자료구조에서 뺀다.** 상태가 줄면 자료구조 고르기가 훨씬 쉬워진다.

# 2번. 필수 간선 포함 MST / 최대 신장 트리

## 문제 복원

- 연결된 **양방향(무방향) 그래프**
- 노드 수 N ≤ 50,000 / 간선 수 M ≤ 200,000
- 배열 `chain = [a1, a2, …, ak]`가 주어짐
  → `(a1,a2), (a2,a3), …, (a_{k-1},a_k)` 간선을 **반드시 포함**해야 함 ("직렬로 연결")
- 모든 노드가 서로 접근 가능해야 함 (분절 불가)

**출력**: 이때 만들 수 있는 그래프의 weight 합의 **최솟값과 최댓값**

## 핵심 아이디어

시험장에서 떠올릴 문장은 **딱 하나**다.

> ### 필수 간선 먼저 다 넣고, 그다음에 평소대로 크루스칼.

이유: 필수 간선은 어차피 **무조건 써야 하니까** 정렬이고 뭐고 그냥 먼저 넣어버리면 된다.
넣고 나면 그 두 노드는 이미 이어진 상태(같은 그룹)가 되고, 나머지는 그냥 평범한 크루스칼이다.

세 조각으로 쪼개면:

1. **"최소 weight로 전부 연결" = MST = 크루스칼** (외우는 것)
   - 간선을 싼 순으로 정렬
   - 앞에서부터 보면서 **사이클을 안 만들면** 넣는다
2. **최댓값은 정렬만 뒤집으면 된다** (최대 신장 트리)
3. **필수 간선은 먼저 넣는다**

> 이론적 근거: 필수 간선을 contract한 그래프의 MST + 필수 간선 = 필수 간선을 포함하는 최소 신장 트리.
> 그리고 원본 간선 리스트를 "이미 union된 DSU" 상태로 크루스칼 돌리는 것 = 축약 그래프에서 크루스칼 돌리는 것과 동일.

## 부품 — Union-Find (사이클 판정기)

크루스칼에서 "이 간선 넣으면 사이클 되나?"를 판정하는 도구. **통째로 외워두고 복붙한다.**

- `parent[x]`: x의 부모. 처음엔 자기 자신
- `find_root(x)`: x가 속한 그룹의 대표를 찾음
- 두 노드의 대표가 **같으면** → 이미 연결됨 → 넣으면 사이클 → **버림**
- **다르면** → 넣고, 한쪽 대표를 다른 쪽에 붙임

```python
def find_root(parent, x):
    # 1단계: 뿌리 찾기
    root = x
    while parent[root] != root:
        root = parent[root]

    # 2단계: 지나온 애들 전부 뿌리에 직접 연결 (경로 압축)
    while parent[x] != root:
        next_node = parent[x]
        parent[x] = root
        x = next_node

    return root
```

2단계(경로 압축)를 빼도 **정답은 나온다.** 다만 느려질 수 있으니 이 8줄은 손에 익혀둘 것.

## 정답 코드

`want_min`만 바꿔서 두 번 호출하는 구조.

```python
def solve_one(n, edges, chain, want_min):
    # edges: (u, v, w) 리스트 / chain: 반드시 직렬 연결돼야 하는 노드 배열
    # want_min: True면 최솟값, False면 최댓값

    parent = list(range(n + 1))
    total = 0        # 지금까지 고른 간선 weight 합
    used = 0         # 지금까지 고른 간선 개수

    # ---- 0. 반드시 써야 하는 (작은노드, 큰노드) 쌍 모으기 ----
    must = set()
    for i in range(len(chain) - 1):
        a = chain[i]
        b = chain[i + 1]
        if a == b:
            continue                  # 자기 자신끼리는 간선이 아님
        if a > b:
            a, b = b, a               # 항상 (작은쪽, 큰쪽)으로 통일
        must.add((a, b))

    # ---- 1. 간선을 '필수'와 '나머지'로 분류 ----
    must_edges = []
    other_edges = []
    for u, v, w in edges:
        a, b = u, v
        if a > b:
            a, b = b, a
        if (a, b) in must:
            must_edges.append((w, u, v))
        else:
            other_edges.append((w, u, v))

    # ---- 2. 정렬 방향 결정 ----
    if want_min:
        must_edges.sort()                  # 싼 순
        other_edges.sort()
    else:
        must_edges.sort(reverse=True)      # 비싼 순
        other_edges.sort(reverse=True)

    # ---- 3. 필수 간선부터 무조건 붙이기 ----
    for w, u, v in must_edges:
        root_u = find_root(parent, u)
        root_v = find_root(parent, v)
        if root_u == root_v:
            continue                  # 같은 쌍의 간선이 여러 개 → 이미 붙음
        parent[root_u] = root_v
        total += w
        used += 1

    if used != len(must):
        return -1                     # 필수 간선이 없거나, 필수끼리 사이클

    # ---- 4. 나머지는 평범한 크루스칼 ----
    for w, u, v in other_edges:
        root_u = find_root(parent, u)
        root_v = find_root(parent, v)
        if root_u == root_v:
            continue                  # 사이클이면 버림
        parent[root_u] = root_v
        total += w
        used += 1

    if used != n - 1:
        return -1                     # 그래프가 끊겨 있음

    return total


def solve(n, edges, chain):
    minimum = solve_one(n, edges, chain, True)
    maximum = solve_one(n, edges, chain, False)
    return minimum, maximum
```

> **3번 블록과 4번 블록은 글자 그대로 똑같다.** 다른 건 리스트 이름뿐.
> 실전에선 4번을 먼저 쓰고 복붙해서 3번을 만드는 식으로 짜면 된다.

## 코드에 담긴 자잘한 처리들

**`(w, u, v)` 순서로 담은 이유**
파이썬 `sort()`는 튜플 첫 원소부터 비교한다. weight를 맨 앞에 두면 `sort()` 한 방에 weight 기준 정렬.
`key=lambda` 안 써도 됨.

**`a > b`면 스왑하는 이유**
간선 `(3, 7)`과 `(7, 3)`은 같은 간선인데 튜플로는 다르다.
항상 작은 쪽을 앞에 두는 규칙을 정해두면 `set`으로 비교 가능.

**평행 간선 (같은 쌍에 간선 여러 개)**
필수 쌍 (3,7)에 weight 5짜리와 9짜리가 둘 다 있다면?
→ 최솟값 구할 땐 싼 순 정렬이라 5가 먼저 들어가고 9는 사이클 판정에 걸려 자동 폐기.
→ 최댓값 땐 반대로 9가 들어감.
**정렬 순서가 알아서 처리해준다. 따로 코드 짤 필요 없음.**

**`used != len(must)` 체크**
필수 간선이 애초에 그래프에 없거나, 필수 간선들끼리 사이클을 이루면(트리가 안 됨) 여기서 걸린다.
문제에서 "항상 가능"을 보장했으면 빼도 됨.

**`chain` 예외 케이스**
- 길이 0 또는 1 → 필수 간선 없음 → 그냥 MST / 최대 신장 트리
- 연속 중복 노드 (`a_i == a_{i+1}`) → self-loop → `continue`로 스킵

## 입력 받는 부분 (필수)

M이 20만이면 `input()`으로 받는 순간 **그것만으로 몇 초 날아간다.** 무조건 붙일 것.

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    idx = 0

    n = int(data[idx]); idx += 1
    m = int(data[idx]); idx += 1

    edges = []
    for _ in range(m):
        u = int(data[idx]); idx += 1
        v = int(data[idx]); idx += 1
        w = int(data[idx]); idx += 1
        edges.append((u, v, w))

    k = int(data[idx]); idx += 1
    chain = []
    for _ in range(k):
        chain.append(int(data[idx])); idx += 1

    print(*solve(n, edges, chain))
```

## 복잡도

정렬 `O(M log M)` × 2회 + DSU 거의 상수 → M = 200,000이면 파이썬으로도 통과권.

## 2번 검증

MST는 눈으로 봐선 맞는지 모른다. 작은 그래프에서 **모든 신장 트리를 전부 만들어보는** 코드로 대조.

```python
from itertools import combinations

def brute(n, edges, chain):
    must = set()
    for i in range(len(chain) - 1):
        a, b = chain[i], chain[i + 1]
        if a != b:
            must.add((min(a, b), max(a, b)))

    best_min, best_max = None, None

    for picked in combinations(edges, n - 1):
        parent = list(range(n + 1))
        ok = True
        for u, v, w in picked:
            ru, rv = find_root(parent, u), find_root(parent, v)
            if ru == rv:
                ok = False        # 사이클 → 트리 아님
                break
            parent[ru] = rv
        if not ok:
            continue

        pairs = set((min(u, v), max(u, v)) for u, v, w in picked)
        if not must.issubset(pairs):
            continue              # 필수 간선 누락

        total = sum(w for u, v, w in picked)
        if best_min is None or total < best_min:
            best_min = total
        if best_max is None or total > best_max:
            best_max = total

    return (best_min if best_min is not None else -1,
            best_max if best_max is not None else -1)
```

노드 5~6개, 간선 7~8개짜리 랜덤 그래프로 1000번 돌려서 `solve`와 비교.

> 브루트포스를 먼저 짜두면 **검증기가 공짜로 생긴다.**
> 시간 남을 때 이거 돌려보는 게 눈으로 코드 노려보는 것보다 훨씬 빠르다.

# 다음 코테를 위한 체크리스트

## 문제 푸는 절차

1. **문제 그대로 브루트포스 짠다** (이중 for문 상관없음)
2. **안쪽 반복문이 무슨 연산인지 이름 붙인다**
   → "최소 찾기", "구간 합", "존재 확인", "정렬 순서 유지"…
3. **그 연산 개수만큼 자료구조를 붙인다**
   → 최소 찾기가 2개면 **힙 2개**
4. **브루트포스와 랜덤 입력 대조** ← 진짜로 할 것

## 파이썬에 TreeSet 없어서 막혔을 때

먼저 자문한다.

> **"내가 진짜 임의 위치 삭제나 lower_bound가 필요한가, 아니면 min만 필요한가?"**

- **min만 필요** → `heapq`. 기준이 여러 개면 **상태별로 힙을 쪼갠다** (1번 문제가 이 케이스)
- **진짜 multiset 필요** → **lazy deletion 패턴**
  - 삭제할 원소를 `dict`(카운터)나 별도 힙에 기록
  - `pop`할 때 "삭제 예정이면 버리고 다시 pop"
  - 각 원소가 최대 1회만 버려지므로 amortized `O(log N)` 유지
