## 1번

- 오류코드 복원하는 문제
- 1~99, -1 이 들어있는 배열
- 1~99가 들어있으면 그대로 answer 배열에 받아적기, -1이면 복원해야 함.
- 복원 규칙은 다음과 같음
- -1이 들어있는 코드의 앞, 뒤를 확인
- 앞 뒤가 모두 -1이거나, 맨앞/맨뒤일 경우(즉 앞뒤로 유효한 코드가 없는 경우) -2를 answer 배열에 넣어줌
- 하나만 -1이면 유효한 코드를 주어진 m으로 나눈 나머지를 answer 배열에 넣어줌
- 둘 다 유효하면, 두 숫자를 작은 순서대로 문자열로 이어붙인 수를 m으로 나눈 나머지를 answer 배열에 넣어줌

## 2번

- 보안 카드 생성기
- origins 카드와 test 카드를 줌
- 2차원 n\*n 배열이고, 각 카드 값은 최대 2 000 000, 각 숫자는 한 번만 나올 수 있음.
- 우리는 두 카드를 비교해서, answer 배열을 리턴해야 함.
- origins[i][j] == test[i][j]인 경우 answer[i][j] = 4
- origins[i][j]가 test의 i열에 존재하는 경우 asnwer[i][j] = 3
- test의 j열에 존재하는 경우 2
- i, j 둘 다 안맞지만 쨌든 존재하는 경우 1
- test에 origins[i][j]가 없는 경우 0
- 나는 이걸 거꾸로 2 000 000짜리 visited 배열을 만들고, ogirins[i][j]가 k라면 visited_origin[k]에 (i, j)를 넣어놨음.
- 같은걸 test에도 진행했음
- 그래서 for i in range, for j in range 해서 origins[i][j]를 now로 하고, test[now]에서 i, j를 뽑아내서 둘 다 일치하면 4, 아니면 3 2 1 0... 이런식으로 했음.

## 6번 sql

- 아 진짜 개아까운데이거
- 결제내역, 적립정책 테이블이 두 개 주어짐
- 적립정책에는 최소결제금액, 카테고리(food, shopping 등), 정책시작일, 정책종료일이 있음 이 네가지를 결제내역이 모두 충족해야 적용가능
- 적립정책에는 적립율과 최소적립금액이 있음
- 적립률곱해서 나온금액, 최소적립금액 중 적은거를 적립시켜줄거임
- 여러 적립정책을 적용시킬수있다면 적립금액이 더 큰놈을, 만약 같다면 적립정책아이디가 작은놈을 적용시켜야 함
- 최종적으로 결제내역id, 적용된적립정책id, 그때의적립금을 리턴

- with 써서 저 적립정책 적용시킨 모든 결제내역 테이블을 만들었음
- 그때의 최대적립금을 max(with에서가져온적립금) 해서 뽑았는데
- 문제가 저 최대적립금을 적용시킨 적립정책id를 들고오는 방법을 모르겠음
